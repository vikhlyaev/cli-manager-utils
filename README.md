# cli-manager

TUI-приложение для конструирования составных команд (**префикс → команда → флаги/аргументы**)
с привязкой bash-скриптов. Управляйте командами через визуальный интерфейс, используйте
глобальные переменные, задавайте контекстные условия для автодополнения — а утилита
сгенерирует готовый скрипт для zsh или bash.

Построено на экосистеме [Charmbracelet](https://charm.sh): Bubble Tea, Lip Gloss, Bubbles, Huh.

## Возможности

- 📁 Иерархия **префикс → команда → подкоманды → … → флаг** с навигацией внутрь
  (Enter) и наружу (Esc); подкоманды любой глубины (`av db migrate up`)
- 🌐 Экран **глобальных переменных** (словарь ключ-значение), экспортируются в скрипт
- ⚠️ Проверка **коллизий** имени префикса с системными утилитами (`command -v`)
  и alias из `~/.zshrc` — префикс становится функцией и может их перекрыть
- ▶️ **Тестовый запуск** bash-кода прямо из формы по `Ctrl+T`
- 🎯 **Контекстные условия** (`condition`): команда появляется в автодополнении,
  только если условие истинно (напр. `[[ -f docker-compose.yml ]]`)
- 🔧 Проброс аргументов `$@` для команд с `accepts_args`
- 💾 Автоматическая генерация ZSH-скрипта — при каждом сохранении и при запуске приложения
- 🛡️ Надёжная запись: конфиг и скрипт пишутся атомарно, а скрипт перед заменой
  проверяется `zsh -n` / `bash -n` — при ошибке остаётся прежний рабочий файл
- 📖 Встроенная справка: голый префикс или `-h`/`--help` печатает список всех команд
  (с описанием аргументов из поля `usage`)
- 🔄 **Авто-перезагрузка**: правки из TUI сразу доступны в уже открытых терминалах
- 🧰 **Командная строка**: `cli-manager init | generate | doctor | path | version`
- ⏸ **Выключение** префикса, команды или флага без удаления; 📄 дублирование по `c`
- 🔎 **Поиск** по спискам (`/`), правка действия во **внешнем редакторе** (`Ctrl+E`)
- 🩺 **Проверка конфига** целиком при запуске — ловит ошибки ручной правки YAML

## Архитектура

```
cmd/cli-manager/        точка входа: без аргументов — TUI, иначе подкоманда
internal/
  cli/                  подкоманды generate, init, doctor, path, version, help
  buildinfo/            версия сборки (подставляется через ldflags)
  shellrc/              подключение скрипта к ~/.zshrc / ~/.bashrc
  models/               структуры Config, Prefix, Command, Flag (YAML-теги)
  storage/              LoadConfig / SaveConfig (~/.config/cli-manager/config.yaml)
  compiler/             интерфейс Compiler, ZshCompiler и BashCompiler
  fsutil/               атомарная запись файлов (временный файл + rename)
  importer/             разбор alias из rc-файла оболочки
  validation/           проверка имён и всего конфига (ValidateConfig), bash -n,
                        коллизии, тестовый запуск
  tui/                  Bubble Tea: меню, списки, формы Huh, UX-валидация
```

- **Конфигурация:** `~/.config/cli-manager/config.yaml`
  (перед каждой перезаписью предыдущая версия сохраняется в `config.yaml.bak`)
- **Сгенерированный скрипт:** `~/.local/share/cli-manager/generated.zsh`
  (или `generated.bash` — в зависимости от выбранной оболочки); рядом лежит
  `generated.<sh>.stamp` — метка поколения для авто-перезагрузки

## Вложенные подкоманды

Команда может быть **листом** (есть действие `run`, опционально флаги) либо
**ветвью-диспетчером** (есть `subcommands` любой глубины), как `git`:
`av db migrate up`. В TUI `Enter` на листе открывает его флаги, а на ветви —
уходит в подкоманды; `s`/`→` всегда входит в подкоманды (чтобы начать
вложенность у листа), `Esc` — на уровень выше. На каждом уровне работают
своя справка (`av db --help`) и автодополнение. Если у команды есть подкоманды,
при генерации они имеют приоритет над флагами, а `run` ветви выполняется как
действие по умолчанию для нераспознанной подкоманды.

```yaml
prefixes:
  - name: av
    commands:
      - name: db
        description: "работа с БД"
        subcommands:
          - name: migrate
            subcommands:
              - name: up
                run: "migrate -path ./migrations up"
              - name: down
                run: "migrate -path ./migrations down"
```

## Импорт alias из rc-файла

В списке префиксов клавиша `i` разбирает rc-файл выбранной оболочки
(`~/.zshrc` для zsh, `~/.bashrc` для bash) и складывает найденные
`alias` командами в префикс-контейнер `imported` (`imported gs` → `git status`).
Имена, недопустимые как имена команд, и уже импортированные пропускаются;
статус показывает, сколько добавлено и пропущено. Импорт обратим по `u`.

## Целевая оболочка (zsh / bash)

Поле `shell` в конфиге (`zsh` по умолчанию) определяет, для какой оболочки
генерируется скрипт. Переключается прямо в TUI — пункт **«Оболочка»** в главном
меню (zsh ↔ bash). Для zsh автодополнение строится на `compdef`/`_arguments`,
для bash — на `complete -F`/`compgen`; диспетчер, справка и контекстные условия
общие. Подключайте соответствующий файл (`generated.zsh` или `generated.bash`).

## Требования

- **Go 1.23+** — для сборки
- **zsh** или **bash** — целевая оболочка для итогового скрипта и автодополнения
- **bash** — используется для проверки коллизий (`command -v`), тестового запуска
  (`Ctrl+T`) и проверки синтаксиса (`bash -n`); итоговый скрипт проверяется
  целевой оболочкой (`zsh -n` / `bash -n`)

## Установка

```bash
make install   # go install с версией из git describe → $(go env GOPATH)/bin
cli-manager init
```

`init` один раз дописывает в конец `~/.zshrc` (или `~/.bashrc` для bash) блок
подключения скрипта — с подтверждением и бэкапом `.bak`:

```zsh
# >>> cli-manager >>>
[ -f "$HOME/.local/share/cli-manager/generated.zsh" ] && source "$HOME/.local/share/cli-manager/generated.zsh"
# <<< cli-manager <<<
```

`init --print` только печатает блок (вставить вручную), `init --yes` не
спрашивает. Если скрипт уже подключён (блоком или своей строкой `source`),
`init` ничего не меняет. Главное меню TUI напоминает, если подключения нет.
Для zsh учитывается `$ZDOTDIR`. На macOS терминал запускает login-bash,
который читает `~/.bash_profile`, — он должен подключать `~/.bashrc`
(`[ -f ~/.bashrc ] && . ~/.bashrc`); `doctor` это проверяет.

> Для автодополнения в zsh нужна инициализированная система completion
> (`autoload -Uz compinit && compinit`), и подключение должно стоять **после**
> неё — `init` дописывает блок в конец файла. `cli-manager doctor` проверит это
> (compinit, вызванный фреймворком — oh-my-zsh, prezto, zinit и др., — тоже засчитывается).

## Командная строка

Без аргументов `cli-manager` открывает TUI, с аргументом — выполняет подкоманду:

| Команда | Что делает |
|---|---|
| `generate` | перегенерировать скрипт из конфига (после ручной правки YAML) |
| `init` | подключить скрипт к rc-файлу оболочки (`--yes`, `--print`) |
| `doctor` | проверить конфиг, скрипт, подключение, compinit и коллизии; код 1 при ошибках |
| `path` | напечатать путь к скрипту — для `source "$(cli-manager path)"` |
| `version` | показать версию (`--version`, `-v`) |
| `help` | список команд (`-h`, `--help`) |

```
$ cli-manager doctor
✓ конфиг: ~/.config/cli-manager/config.yaml
✓ конфиг без ошибок (префиксов: 2)
✓ целевая оболочка: zsh
✓ скрипт: ~/.local/share/cli-manager/generated.zsh
✓ скрипт подключён в ~/.zshrc
✓ автодополнение: compinit найден
✓ коллизий имён префиксов нет
```

## Как скрипт попадает в оболочку

Скрипт перегенерируется автоматически: при каждом сохранении изменений в TUI, а
также при каждом **запуске приложения** (чтобы улучшения генератора попадали в
скрипт без правок конфигурации).

**Открытые терминалы подхватывают изменения сами.** Скрипт регистрирует хук
(`precmd` в zsh, `PROMPT_COMMAND` в bash), который перед каждым приглашением
сравнивает метку поколения из `generated.<sh>.stamp` со своей. Если скрипт
перегенерирован, хук снимает функции прежних префиксов (удалённые исчезают) и
заново подключает скрипт. Метка — хеш текста скрипта, поэтому повторная
генерация без изменений перезагрузки не вызывает.

Любой префикс показывает справку со списком всех команд, если вызвать его без
аргументов или с `-h`/`--help` (а неизвестная команда печатает ту же справку в
stderr):

```
$ av
av — Мой персональный тулкит

Использование: av <команда> [аргументы]

Команды:
  note <текст>  Создать быструю заметку
  deploy        Развернуть проект
      --force   Пересобрать контейнеры
```

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `↑/↓`, `j/k` | навигация |
| `Enter` | открыть / сохранить |
| `n` | создать элемент |
| `e` | редактировать |
| `d` | удалить (с подтверждением `y`/`n`) |
| `c` | дублировать (команду — со всеми флагами и подкомандами) |
| `x` | выключить / включить (остаётся в конфиге, но не попадает в скрипт) |
| `/` | поиск по имени (`Enter` — применить, `Esc` — сбросить) |
| `?` | все клавиши |
| `Shift+↑/↓`, `K/J` | переместить элемент (порядок влияет на справку и автодополнение) |
| `Enter` (на команде) | лист → флаги команды; ветвь (есть подкоманды) → внутрь |
| `s` / `→` (на команде) | войти в подкоманды (в т.ч. чтобы начать вложенность у листа) |
| `f` (на команде) | открыть флаги команды (явно) |
| `p` | предпросмотр сгенерированного кода префикса (весь скрипт — пункт главного меню) |
| `i` | импорт alias из `~/.zshrc`/`~/.bashrc` в префикс `imported` (в списке префиксов) |
| `u` | отменить последнее изменение (создание/правка/удаление/перемещение) |
| `Esc` | назад / отмена |
| `Ctrl+T` | тестовый запуск bash-кода (в форме) |
| `Ctrl+E` | открыть действие во внешнем редакторе (`$VISUAL` → `$EDITOR` → `nano`) |
| `Ctrl+C` | выход |

Формы валидируют ввод на лету: имена проверяются на формат (shell-идентификатор)
и уникальность, поле `condition` — на синтаксис, а bash-код поля `run`
подсвечивает ошибки синтаксиса (`bash -n`) прямо во время набора, не выполняя код.
Если команда с ошибкой всё же сохранена, конфиг запишется, но скрипт не
обновится, пока ошибку не исправить, — статус-строка покажет причину.

> ⚠️ `Ctrl+T` **реально выполняет** введённый bash-код в текущем окружении
> и показывает его stdout/stderr. Не тестируйте деструктивные команды.

## Пример config.yaml

```yaml
variables:
  VAULT_DIR: "~/Documents/vault"

prefixes:
  - name: av
    description: "Мой персональный тулкит"
    commands:
      - name: note
        description: "Создать быструю заметку"
        usage: "<текст>"             # показывается в справке
        run: "echo \"$@\" >> ${VAULT_DIR}/inbox.md"
        accepts_args: true
      - name: deploy
        description: "Развернуть проект"
        run: "docker-compose up -d"
        condition: "[[ -f docker-compose.yml ]]"
        flags:
          - name: --force
            description: "Пересобрать контейнеры"
            run: "docker-compose up -d --build"
      - name: legacy
        run: "./old-deploy.sh"
        disabled: true               # в конфиге, но не в скрипте
```

Конфиг можно править вручную: при запуске (и в `cli-manager doctor`) он
проверяется целиком — формат имён, дубли, синтаксис условий. После ручной
правки выполните `cli-manager generate` или просто откройте TUI.
