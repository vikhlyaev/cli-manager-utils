# cli-manager

TUI-приложение для конструирования составных команд (**префикс → команда → флаги/аргументы**)
с привязкой bash-скриптов. Управляйте командами через визуальный интерфейс, используйте
глобальные переменные, задавайте контекстные условия для автодополнения — а утилита
сгенерирует готовый ZSH-скрипт.

Построено на экосистеме [Charmbracelet](https://charm.sh): Bubble Tea, Lip Gloss, Bubbles, Huh.

## Возможности

- 📁 Иерархия **префикс → команда → флаг** с навигацией внутрь (Enter) и наружу (Esc)
- 🌐 Экран **глобальных переменных** (словарь ключ-значение), экспортируются в скрипт
- ⚠️ Проверка **коллизий** имени команды с системными утилитами (`command -v`)
- ▶️ **Тестовый запуск** bash-кода прямо из формы по `Ctrl+T`
- 🎯 **Контекстные условия** (`condition`): команда появляется в автодополнении,
  только если условие истинно (напр. `[[ -f docker-compose.yml ]]`)
- 🔧 Проброс аргументов `$@` для команд с `accepts_args`
- 💾 Автоматическая генерация ZSH-скрипта — при каждом сохранении и при запуске приложения
- 📖 Встроенная справка: голый префикс или `-h`/`--help` печатает список всех команд

## Архитектура

```
cmd/cli-manager/        точка входа (main.go)
internal/
  models/               структуры Config, Prefix, Command, Flag (YAML-теги)
  storage/              LoadConfig / SaveConfig (~/.config/cli-manager/config.yaml)
  compiler/             интерфейс Compiler + ZshCompiler (генерация generated.zsh)
  validation/           CheckCollision, ValidateBash (тест), CheckSyntax (bash -n)
  tui/                  Bubble Tea: меню, списки, формы Huh, UX-валидация
```

- **Конфигурация:** `~/.config/cli-manager/config.yaml`
  (перед каждой перезаписью предыдущая версия сохраняется в `config.yaml.bak`)
- **Сгенерированный скрипт:** `~/.local/share/cli-manager/generated.zsh`
  (или `generated.bash` — в зависимости от выбранной оболочки)

## Целевая оболочка (zsh / bash)

Поле `shell` в конфиге (`zsh` по умолчанию) определяет, для какой оболочки
генерируется скрипт. Переключается прямо в TUI — пункт **«Оболочка»** в главном
меню (zsh ↔ bash). Для zsh автодополнение строится на `compdef`/`_arguments`,
для bash — на `complete -F`/`compgen`; диспетчер, справка и контекстные условия
общие. Подключайте соответствующий файл (`generated.zsh` или `generated.bash`).

## Требования

- **Go 1.23+** — для сборки
- **zsh** — целевая оболочка для итогового скрипта и автодополнения
- **bash** — используется для проверки коллизий (`command -v`), тестового запуска
  (`Ctrl+T`) и проверки синтаксиса (`bash -n`)

## Сборка и запуск

Через `make`:

```bash
make run    # запустить приложение (по умолчанию)
make test   # прогнать тесты
make fmt    # отформатировать код
make vet    # статический анализ
make help   # список всех целей
```

При каждом `make run` скрипт `generated.zsh` перегенерируется на старте, поэтому
изменения сразу попадают в оболочку — достаточно открыть новый терминал или
выполнить `source ~/.zshrc`.

## Подключение к оболочке

Добавьте в `~/.zshrc` (один раз):

```zsh
source ~/.local/share/cli-manager/generated.zsh
```

> Для работы автодополнения система completion должна быть инициализирована
> (`autoload -Uz compinit && compinit` — обычно уже есть в `~/.zshrc`).
> Регистрация `compdef` защищена проверкой, поэтому скрипт безопасно
> подключать и в неинтерактивных сессиях.

Скрипт перегенерируется автоматически: при каждом сохранении изменений в TUI, а
также при каждом **запуске приложения** (чтобы улучшения генератора попадали в
скрипт без правок конфигурации). Достаточно открыть новый терминал или выполнить
`source ~/.zshrc`.

Любой префикс показывает справку со списком всех команд, если вызвать его без
аргументов или с `-h`/`--help` (а неизвестная команда печатает ту же справку в
stderr):

```
$ av
av — Мой персональный тулкит

Использование: av <команда> [аргументы]

Команды:
  note    Создать быструю заметку
  deploy  Развернуть проект
```

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| `↑/↓`, `j/k` | навигация |
| `Enter` | открыть / сохранить |
| `n` | создать элемент |
| `e` | редактировать |
| `d` | удалить (с подтверждением `y`/`n`) |
| `Shift+↑/↓`, `K/J` | переместить элемент (порядок влияет на справку и автодополнение) |
| `p` | предпросмотр сгенерированного zsh для префикса |
| `u` | отменить последнее изменение (создание/правка/удаление/перемещение) |
| `Esc` | назад / отмена |
| `Ctrl+T` | тестовый запуск bash-кода (в форме) |
| `Ctrl+C` | выход |

Формы валидируют ввод на лету: имена проверяются на формат (shell-идентификатор)
и уникальность, поле `condition` — на синтаксис, а bash-код поля `run`
подсвечивает ошибки синтаксиса (`bash -n`) прямо во время набора, не выполняя код.

> ⚠️ `Ctrl+T` **реально выполняет** введённый bash-код в текущем окружении
> и показывает его stdout/stderr. Не тестируйте деструктивные команды.

## Пример config.yaml

```yaml
variables:
  VAULT_DIR: "~/Documents/vault"

prefixes:
  - name: av
    description: "Мой персональный тулкит"
    commands:
      - name: note
        description: "Создать быструю заметку"
        run: "echo \"$@\" >> ${VAULT_DIR}/inbox.md"
        accepts_args: true
      - name: deploy
        description: "Развернуть проект"
        run: "docker-compose up -d"
        condition: "[[ -f docker-compose.yml ]]"
        flags:
          - name: --force
            description: "Пересобрать контейнеры"
            run: "docker-compose up -d --build"
```
